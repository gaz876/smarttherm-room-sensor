# Experimental measurement settings

NVS namespace room_measure, key settings, version 1, a single 12-byte little-endian record (RS, version, reserved, interval in milliseconds, correction in millidegrees C biased by 10000). Range: 1000–3600000 ms, -10000–10000 mdeg. Default 10 s / 0 C (interval from Kconfig). Humidity unchanged.

Startup loads read-only. Missing/invalid/unsupported/I/O status is explicit; fallback defaults are not written automatically. No partition erase on NVS initialization failure. Save/reset helpers are single-owner operations, not invoked at boot or per sample. The internal task-context API now accepts one outstanding command, returns a ticket and reports the last result until a new command is accepted. Only the measurement owner saves or resets, reads back the record, and applies verified settings. The caller must serialize and consume its result before the next request. No authenticated UI exists yet. No-op saves do not write. Explicit reset can replace unsupported data, never erases other keys. On write/commit failure report failure; active settings remain unchanged, the error status is visible, and a later reboot may load a record actually committed before an error was reported. A successful or unchanged save requires exact readback before applying. Hardware power-loss and real NVS testing remain required.

I2C recovery reapplies the loaded interval and correction. The measurement owner publishes a copy under a short FreeRTOS critical section; readers call room_runtime_snapshot in task context, with freshness calculated at read time and settings status available. No I2C or NVS calls under the lock. Future transport must check both sample validity and configuration status; invalid/unsupported/I/O configuration fallback is not cleared for heating use.

Host tests use a fake store and actual app source against a mock SDK, not real flash or a concurrent scheduler. Dedicated runner: sh tests/run_settings_host.sh. Target build and archive verified in run 45729696843; the newer runtime-command candidate has host evidence only; its target build, hardware validation, real task concurrency and authenticated user-facing save/reset path remain pending. No Wi-Fi, MQTT, OTA, heating or production changes.
